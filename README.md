# منصة إدارة مكتب رجل الأعمال

منصة عربية (RTL) تجمع التكليفات والمهام والمحادثات والاعتمادات والاجتماعات والإجراءات والشراكات والتقارير بين حسابين: **رجل الأعمال** و**مدير المكتب**، مع قاعدة بيانات دائمة ومزامنة فورية بين الحسابين. تعمل على الجوال والكمبيوتر، ويمكن تثبيتها على الجوال كتطبيق (PWA).

## التشغيل

المتطلبات: Node.js 22.13 أو أحدث (تُستخدم قاعدة SQLite المدمجة في Node، فلا حاجة لخادم قاعدة بيانات منفصل).

```bash
npm install
npm start
```

ثم افتح `http://localhost:3000`.

- عند أول تشغيل يُنشأ الحسابان تلقائيًا، وتُطبع كلمات المرور الأولية في الطرفية وتُحفظ في `data/initial-credentials.txt`. غيّرها من صفحة **الإعدادات** بعد أول دخول.
- اسما المستخدمين الافتراضيان: `owner` (رجل الأعمال) و`manager` (مدير المكتب). يمكن تحديد الأسماء وكلمات المرور مسبقًا عبر `.env` (انظر `.env.example`).
- للوصول من جوال على نفس الشبكة: `http://<عنوان-الجهاز>:3000`. ملاحظة: الإشعارات الفورية والتسجيل الصوتي يتطلبان HTTPS خارج `localhost`.

### التجربة على GitHub Codespaces (بدون تثبيت)

المستودع مُعد للتشغيل في Codespaces (`.devcontainer/devcontainer.json`):
1. في صفحة المستودع: **Code ← Codespaces ← Create codespace on main**.
2. ينتظر تثبيت الحزم، ثم تبدأ المنصة تلقائيًا في الطرفية وتُطبع كلمات المرور الأولية (ومحفوظة أيضًا في `data/initial-credentials.txt`).
3. من تبويب **PORTS** يظهر رابط HTTPS للمنفذ 3000. هو **خاص** افتراضيًا (لا يفتحه إلا صاحب الـ Codespace بعد تسجيل الدخول في GitHub). لكي يفتحه الطرف الآخر من جواله: زر الفأرة الأيمن على المنفذ ← **Port Visibility ← Public**.

تنبيهات مهمة:
- الرابط العام يفتحه **أي شخص** يملك الرابط (تظهر له صفحة الدخول فقط)، فاستخدم كلمات مرور قوية ولا تُدخل بيانات حساسة حقيقية أثناء التجربة.
- يتوقف الـ Codespace بعد فترة خمول، فيتوقف الرابط. عند إعادة تشغيله تعود المنصة للعمل ويعود المنفذ **خاصًا**، فيلزم جعله عامًا من جديد.
- البيانات تبقى داخل الـ Codespace ما دام موجودًا، وتُحذف بحذفه. هذه بيئة تجربة وليست استضافة دائمة.
- يُحتسب الاستخدام من الحصة الشهرية المجانية للحساب الشخصي في GitHub، وما زاد عنها يُحتسب بتكلفة.

## طريقة الاستخدام

### رجل الأعمال
- **+ تكليف جديد** (أعلى الشاشة دائمًا): العنوان، الوصف، أحد الأقسام الستة، الأهمية (عادي/مهم/عاجل)، الموعد، مرفقات وصور وملاحظة صوتية. يحصل التكليف على رقم مرجعي مثل `TK-2026-0001` ويصل فورًا لمدير المكتب مع إشعار.
- **إرسال ملاحظة أو طلب**: للاطلاع، طلب إجراء، تعديل على مهمة، استفسار، توجيه/قرار. يمكن ربطها بمهمة قائمة فتظهر داخل محادثتها. لا تتحول إلى مهمة تلقائيًا.
- **طلباتي وتكليفاتي**: كل ما أرسلته مع الحالة والمسؤول وآخر تحديث، مع البحث والتصفية.
- **بانتظار قراري**: اعتماد، رفض مسبّب، طلب تعديل، اختيار بديل، أو الرد على استفسار. يُسجَّل القرار وصاحبه ووقته ويصل إشعار لمدير المكتب. **تسجيل الاعتماد لا يُنفّذ أي إجراء مالي أو تعاقدي خارجي.**
- داخل أي مهمة: قراءة كل المحادثة والتحديثات والملفات والقرارات، وإرسال ملاحظة.

### مدير المكتب
- **الوارد من رجل الأعمال**: تأكيد الاستلام، التحويل إلى مهمة (في السجل نفسه دون نسخة مكررة، مع الاحتفاظ بالنص الأصلي)، ثم تحديد المسؤول والموعد والخطوة التالية.
- **داخل المهمة**: بدء التنفيذ، بانتظار رد طرف خارجي، متعثرة، تحديثات تنفيذ، **طلب اعتماد/قرار** (مع بدائل ومرفقات، ويمكن تحديد أنه «يعطل التنفيذ»)، **رفع النتيجة النهائية**، **إغلاق نهائي**.
- **لوحة المتابعة**: مهام اليوم، العاجلة، المتأخرة، غير المؤكدة، التي لم تبدأ، التي تنتظر معلومات/اعتماد/أطرافًا خارجية، المتعثرة، والمكتملة التي تنتظر الإغلاق. تحديث الحالة سريعًا من القائمة.
- الاجتماعات والقرارات، الإجراءات التشغيلية، العلاقات والشراكات، المشاريع داخل كل قسم.

### قواعد العمل المطبقة
| القاعدة | التطبيق |
|---|---|
| شريط **مهام اليوم** (برتقالي) | كل مهمة/تكليف مفتوح موعده اليوم، أيًا كانت أولويته |
| شريط **المهام العاجلة** (أحمر) | (1) أولوية «عاجل» (2) متأخرة وأولويتها «مهم» أو «عاجل» (3) متعثرة (4) تنتظر قرارًا من رجل الأعمال مُعلَّمًا بأنه يعطل التنفيذ. المستحقة اليوم ليست عاجلة تلقائيًا |
| الحركة | تتوقف عند المرور أو التركيز، وزر إيقاف/تشغيل محفوظ، وتُلغى تمامًا مع إعداد «تقليل الحركة» في الجهاز |
| الفصل بين المراحل | الاستلام (`acknowledged_at`) منفصل عن الحالة، وبدء التنفيذ (`started_at`)، والإنجاز (`completed_at`)، والاعتماد (جدول `approvals`)، والإغلاق النهائي (`closed_at`) |
| سياسة الإغلاق | المهمة المعلَّمة «تتطلب اعتماد النتيجة» لا تصبح «مكتملة» ولا تُغلق إلا بعد اعتماد رجل الأعمال للنتيجة النهائية |
| منع التكرار | التحويل إلى مهمة يتم في السجل نفسه؛ قرار الاجتماع يرتبط بمهمة واحدة فقط (قيد فريد)؛ الملاحظة لا تنشئ مهمة تلقائيًا |
| الصلاحيات | تُفحص في الخادم لكل عملية (`src/domain.js` → `PERMS`)، لا بإخفاء الأزرار فقط |

## الإشعارات

| المستوى | الحالة |
|---|---|
| 1. داخل المنصة | يعمل: مركز إشعارات بعدد غير المقروء، تنبيه منبثق فوري، ربط بالمهمة، دمج الرسائل المتتالية، عدم تكرار تنبيهات المواعيد والتأخر، ملخص يومي، تخصيص لكل مستخدم |
| 2. Push للجوال | مُنفّذ (PWA + Service Worker + مفاتيح VAPID تُولَّد تلقائيًا). يتطلب **HTTPS** في التشغيل الفعلي. على iPhone: إضافة المنصة للشاشة الرئيسية (iOS 16.4+). التفاصيل لا تظهر على شاشة القفل افتراضيًا |
| 2. البريد الإلكتروني | مُنفّذ عبر SMTP لكنه **معطل افتراضيًا** (`EMAIL_MODE=off`). يُفعَّل بإعداد مزود SMTP، ثم يوافق كل مستخدم من الإعدادات |
| 3. واتساب | مُهيأ في `src/whatsapp.js` لـ WhatsApp Business Platform (Cloud API) الرسمية فقط، **معطل ولم يُختبر مع حساب حقيقي** |

سجل محاولات الإرسال خارج المنصة يظهر في صفحة الإعدادات (جدول `deliveries`).

## البنية التقنية

```
src/db.js        قاعدة البيانات (SQLite دائمة) والجداول والنسخ الاحتياطي
src/domain.js    الأقسام، الحالات، الصلاحيات، قواعد الأشرطة والمربعات والتقارير
src/services.js  سير العمل: تكليف، استلام، تحويل، حالات، محادثة، اعتمادات (مع سجل التغييرات)
src/notify.js    الإشعارات: داخل المنصة + Push + البريد
src/events.js    المزامنة الفورية بين الحسابين (Server-Sent Events)
src/server.js    واجهة API والجلسات والملفات والمهام المجدولة
public/          الواجهة (HTML/CSS/JS بدون أطر) + PWA
data/            قاعدة البيانات والملفات المرفوعة والنسخ الاحتياطية (لا تُرفع إلى Git)
```

- **الأمان**: كلمات المرور بخوارزمية scrypt، جلسات بكعكة HttpOnly/SameSite، حماية CSRF بترويسة مخصصة، تحديد محاولات الدخول، سياسة CSP، الملفات تُخدم فقط للمستخدمين المسجلين وبترويسة sandbox.
- **النسخ الاحتياطي**: نسخة تلقائية يوميًا في `data/backups` (آخر 14)، ويدويًا من الإعدادات أو `npm run backup`. للحماية الحقيقية انسخ مجلد `data/` دوريًا إلى مكان آخر خارج الخادم.
- **إضافة مستخدمين مستقبلًا**: الأدوار والصلاحيات في `PERMS` قابلة للتوسعة (مثل دور مساعد بلا صلاحية `contacts.view` لحجب بيانات التواصل).

## النشر على الإنترنت

المنصة تحتاج خادمًا يعمل باستمرار مع **قرص دائم** (قاعدة البيانات والملفات محلية) و**HTTPS**. في المستودع ملفان جاهزان:
- `render.yaml`: نشر بنقرة على Render (الخيار الموصى به).
- `Dockerfile`: لأي استضافة تدعم الحاويات (Railway، Fly.io، خادم خاص). البيانات في `/data` ويجب ربطه بقرص دائم.

### الخيار الموصى به: Render
التكلفة التقريبية: خطة Starter بـ 7 دولارات شهريًا + القرص 0.25 دولار لكل GB شهريًا (القرص 1 GB) ≈ **7.25 دولار شهريًا**. الخطة المجانية لا تصلح لأنها لا تدعم الأقراص الدائمة.

1. أنشئ حسابًا على https://render.com (يمكن الدخول بحساب GitHub)، وأضف وسيلة دفع.
2. **New ← Blueprint**، ثم اختر المستودع `drtasks` واسمح لـ Render بالوصول إليه.
3. سيطلب Render قيمتي `OWNER_PASSWORD` و`MANAGER_PASSWORD`: اكتب كلمتي مرور قويتين (8 أحرف على الأقل) واحفظهما. لا تُطبعان في السجلات.
4. **Apply**. بعد دقائق يظهر رابط مثل `https://drtasks.onrender.com` بشهادة HTTPS جاهزة.
5. (اختياري) ربط نطاق خاص مثل `office.taseel.org.sa` من **Settings ← Custom Domains** بإضافة سجل CNAME لدى مزود النطاق.

بعدها: كل تحديث يُدفع إلى الفرع `main` يُنشر تلقائيًا. المنطقة المضبوطة هي فرانكفورت (أقرب منطقة متاحة في Render للمملكة). يأخذ Render لقطة يومية للقرص تُحفظ 7 أيام على الأقل، إضافة إلى النسخ الاحتياطية اليومية داخل المنصة. ملاحظة: الخدمة ذات القرص الدائم تتوقف لحظات أثناء كل نشر جديد.

### بدائل
| الخيار | التكلفة التقريبية | ملاحظات |
|---|---|---|
| Railway | اشتراك Hobby بـ 5 دولارات شهريًا يشمل 5 دولارات استخدام، والتخزين 0.15 دولار لكل GB | يبني `Dockerfile` تلقائيًا. أضف Volume على المسار `/data` وعرّف المتغيرات يدويًا (`COOKIE_SECURE=1`، `TRUST_PROXY=1`، كلمتي المرور). الصورة تعمل بمستخدم غير root، لذا يلزم `RAILWAY_RUN_UID=0` ليتمكن من الكتابة على الـ Volume |
| خادم خاص (VPS) | من بضعة دولارات شهريًا | تحكم كامل ويمكن اختيار مزود داخل المملكة، لكنه يحتاج إدارة تقنية (تحديثات، HTTPS عبر Caddy/Nginx أو Cloudflare Tunnel) |
| Cloudflare | — | لا يشغّل المنصة بشكلها الحالي (لا قرص دائم ولا SQLite)؛ يصلح بوابة أمام خادم دائم |

### قبل النشر الفعلي
- مكان البيانات: Render وRailway خارج المملكة؛ راجع متطلبات نظام حماية البيانات الشخصية إن كانت ستُحفظ بيانات شخصية.
- البريد الإلكتروني معطل (`EMAIL_MODE=off`) حتى يُضبط مزود SMTP.
- إشعارات الجوال تعمل تلقائيًا مع HTTPS؛ على iPhone يلزم إضافة المنصة للشاشة الرئيسية.
